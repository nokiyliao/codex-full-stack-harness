# Tura-to-Codex Kernel Migration

The Tura fork remains the historical source boundary until every extracted module
has a recorded source preimage and an accepted native Codex replacement.

## Ordered acceptance

1. **Inventory**: classify each imported module as retained, rewritten, or retired.
2. **Provenance**: bind retained code to its exact upstream and modified source.
3. **Native ownership**: prove Codex owns the provider session and outer task loop.
4. **Contract parity**: replay lease, CAS, receipt, recovery, callback, and ACK cases.
5. **Isolated canary**: verify one native plugin candidate without shared adoption.
6. **Installed adoption**: bind installed bytes to the accepted candidate.
7. **Live acceptance**: verify a fresh task through the installed stack.
8. **Tura archive**: archive the standalone fork only after no installed path uses it.

## Migration is not complete when

- source tests pass but no native Codex path exercised the code;
- a candidate binary exists but installed bytes differ;
- a callback was delivered but parent acknowledgement did not converge;
- an old Tura process, binary, or state store still owns active execution;
- provenance or license notices are missing for retained Tura-derived code.
